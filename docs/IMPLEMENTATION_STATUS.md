### Reality vs. Plan Deviations

These are places where the actual codebase diverges from what was planned or assumed:

1. **PayrollManagementPage has no registered route.** The page was built and lazy-imported but never added to the `<Routes>` tree in `App.jsx`. It is completely unreachable from the UI. This is likely a forgotten step, not intentional.

2. **`payrollRoutes.js` is the old stub system, not the new one.** All references to "payroll routes" in early planning were about the new Payrun/Payslip system. What's actually mounted at `/api/payroll` is a placeholder that returns hardcoded dummy data and checks for the dead `'HR'` role. The new system's models (Payrun, Payslip, SalaryStructure, SalaryRule) have no corresponding routes.

3. **`getActiveContractForPeriod` is defined but never called.** The static method is well-implemented in `Contract.js` and even has a doc comment saying it's "Used by the payslip computation engine" — but that engine doesn't exist. This creates a false impression of completeness when reading the model file.

4. **Allocation balance enforcement is advisory, not gated.** The spec implies leave approval should fail if no Allocation covers it. The actual implementation (confirmed in `admin.js`) approves the leave regardless, using `User.leaveBalances` as the source of truth, and only attempts to update `Allocation.takenAmount` as a non-blocking afterthought. `leaveBalances` and `Allocation` are two parallel balance systems rather than one.

5. **`EmployeeForm.jsx` role dropdown uses old `'HR'` enum value**, not the new graduated roles. Creating a new employee via this form would store `role: 'HR'` which doesn't match the current User model enum (the schema does NOT include `'HR'`). This would either fail Mongoose validation silently or persist a non-enumerated role value. The form is also unreachable from the new HR sub-roles (they see the EmployeesPage but the role guard in EmployeeForm shows `'HR'` as the only HR option).

6. **Shift model is a single daily block, not a weekly schedule.** The spec calls for day-by-day (Mon/Tue/.../Sun) definitions with per-day start/end/break. What was built is a single `startTime`/`endTime` template applied uniformly every workday. This is a structural deviation that would require a schema redesign to fix properly.

7. **`PAYROLL_READ`, `PAYROLL_WRITE`, and `SALARY_CONFIG_WRITE` constants in `roles.js` are never used.** These were defined with the correct graduated permissions but no route file imports them. The role guard in `payrollRoutes.js` still checks for the dead `'HR'` role, blocking all new payroll roles including `HRPayrollManager`.

8. **Smart button comments say "no Contract model yet"** — but `Contract.js` was in fact built (with full overlap validation and `getActiveContractForPeriod`). The comment in `admin.js` and the disabled chips in `AdminEmployeeProfileDialog` are stale and don't reflect the current state of the backend model layer.
